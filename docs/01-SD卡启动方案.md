## 一、上次为什么变砖（根因）

**不是 USB 驱动问题，也不是 SD 卡问题，是 boot.img 打包时踩了 4 字节的坑。**

原版 `boot_orig.img` 结构（header **version 0**，page_size 2048）：

| 字段 | 值 |
|---|---|
| kernel_size | **9500581** |
| kernel 起始偏移 | 0x800 |
| kernel + appended DTB 结束 | 0x90ffa5 |
| ramdisk 偏移 | 0x910000 |

关键点：**`kernel_size` 里包含了 appended DTB**（DTB magic 在 0x903f5c，正好落在 kernel_size 范围内）。

改 `dr_mode` 时 `"otg"` → `"host"` 多 1 个字符，dtc 按 4 字节对齐后 DTB 从 **49225 → 49229 字节（+4）**。

上一版打包脚本只做了「DTB 原位替换」，**忘了同步更新 header 的 `kernel_size`**：

```
header 说 kernel 只有 9500581 字节，实际需要 9500585
→ LK(aboot) 只加载 9500581 字节
→ appended DTB 尾部 4 字节被截断
→ DTB 的 totalsize 说 49229，实际数据只有 49225
→ 设备树校验失败 → 内核根本没跑起来
```

现象就是「完全起不来」，连内核日志都没有。

### 已排除的猜测

内核配置全查了，这些**全是 builtin**，「initramfs 缺 USB 模块」的猜测不成立：

```
CONFIG_USB_CHIPIDEA=y  CONFIG_USB_CHIPIDEA_HOST=y  CONFIG_USB_CHIPIDEA_MSM=y
CONFIG_PHY_QCOM_USB_HS=y  CONFIG_USB_STORAGE=y  CONFIG_BLK_DEV_SD=y  CONFIG_MMC_BLOCK=y
```

| 设备端副本 | `/root/boot_v2.img`、`/root/boot_bak_before_v2.img`（原版备份）|

### 为什么保留 `extcon` 属性

DT 里 `usb@78d9000` 有 `extcon = <0x87 0x87>`（指向 `usb-id` 节点，ID 脚 GPIO 500）。

按 chipidea 驱动逻辑，`dr_mode = "host"` 时初始 role 就是 `CI_ROLE_HOST`，extcon notifier 只在 OTG 模式下才决定 role。之前在运行时 unbind 过 extcon-usb-gpio 导致 ci_hdrc `-EPROBE_DEFER`，所以**没动 extcon**。实测也证明这个判断正确 —— 启动后 `cat /sys/kernel/debug/usb/ci_hdrc.0/role` 返回 `host`。

### 为什么用 dd 而不是 fastboot

棒子只有一个 USB 口，插着 hub 就没法连电脑进 fastboot，**没法做 `fastboot boot` 无损测试**。所以改成在系统里直接 `dd` 写 boot 分区：

```bash
dd if=/root/boot_v2.img of=/dev/mmcblk0p12 bs=1M
sync
cmp /root/boot_v2.img /dev/mmcblk0p12    # 必须完全一致
reboot
```

写入前后都做了 MD5 + cmp 双重校验，写入前还确认了当前 boot 分区 == 原版备份（`85f9c9fc...`），确保救砖链路有效。

## 四、运维手册（重要）

### ⚠️ 换卡 / 重刷 SD 卡：必须保持磁盘签名

boot 分区的 cmdline 写死了 `root=PARTUUID=8306c78f-01`。**换一张新卡或重新分区后，MBR 磁盘签名会变，PARTUUID 就对不上，设备会起不来。**

新卡分区后强制写回签名：

```bash
sfdisk --disk-id /dev/sda 0x8306c78f
```

或者直接用备份的分区表恢复（会自动带上签名）：

```bash
sfdisk /dev/sda < sda_partition_table.txt
sfdisk --disk-id /dev/sda        # 确认输出 0x8306c78f
```

### 制作 rootfs 恢复包（建议现在就做一份）

在 SD 卡系统上执行：

```bash
cd /
tar -czpf /mnt/data/rootfs_backup_$(date +%Y%m%d).tar.gz \
    --exclude=/proc --exclude=/sys --exclude=/dev \
    --exclude=/run --exclude=/tmp --exclude=/mnt/data \
    --exclude=/lost+found --exclude=/swapfile \
    --one-file-system /
```

当前 rootfs 约 **882M**，打包后约 300~400M。

恢复时：新卡分区 → 挂载 sda1 → `tar -xzpf` → 写签名 → 搞定，**不需要动 eMMC**。

### 救砖

SD 卡挂了/没插时，设备会卡在 initramfs 起不来。此时：

1. 拔掉 hub，用 USB 线连电脑，进 fastboot
2. 运行 `F:\安卓折腾资料\随身wifi\debian\uz801-debian超频版\一键只刷boot\救砖_刷回原版boot.bat`
   （刷回原版 boot.img，MD5 `85f9c9fceacc4736ed45bcc657190305`，root 回到 mmcblk0p14）
3. 原版镜像本地也有一份：`boot_orig.img`

**eMMC 的 rootfs（mmcblk0p14，1.1G）已验证可正常挂载**，救砖后能完整启动，所以这条路是通的 —— 建议**不要格式化它**，留作紧急 fallback。

### 启动时序（实测）

```
[  2.864s] usb 1-1   hub 出现
[  3.416s] usb 1-1.1 RTL8152 网卡
[  3.812s] usb 1-1.2 SD 读卡器
[  5.097s] sda attached (SCSI)
[ 23.753s] sda1 挂载为 root     ← rootdelay=20 生效，白等了约 15 秒
```

### 可选优化：把 rootdelay 从 20 降到 10

sda 在 **5.1 秒**就就绪了，`rootdelay=20` 让 initramfs 干等到 20 秒才挂载，多花了约 15 秒。改成 10 大约能让启动快 15 秒（总启动时间 40s → 28s 左右），冷启动留 2 倍余量足够。

需要重新打包 boot.img 再 dd 一次，属于低风险操作（流程已验证）。

## 五、参考资料要点（用户提供的两篇）

1. **root= 的写法**：可用主次设备号（`root=179:2` = mmcblk0p2）、`/dev/sdX1` 或 PARTUUID。主次设备号最稳，不依赖 udev/blkid。**若将来 PARTUUID 反复出问题，可退化成 `root=8:1`（8=sda, 1=sda1），换卡不用改 boot。**
2. **rootfstype 必须和 SD 卡格式一致**（这里是 ext4）。
3. **rootdelay 必须给足**（网友用 3，USB 设备建议 10~20）。
4. **console 节点必须和设备树串口一致**（本设备 `ttyMSM0`，已在原 cmdline 中验证）。
5. **rootfs 复制要用 `cp -arf`**（保链接和权限）。
6. **设备树要改**（本方案是改 `dr_mode`）。

### 布局（精简到 11G，任何 ≥16G 的卡都能烧）

```
MBR label-id 0x8306c78f
├─ sda1  6G  ext4  sdroot   系统（实际数据 880MB）
├─ sda2  4G  ext4  sddata   数据盘
└─ sda3  1G  swap  sdswap
```

### 制作方式（在设备上完成，无需 PC 端工具）

关键技巧是 **mkfs.ext4 的 `-d` 参数** —— 可以不用 loop 挂载、不用 kpartx，直接把目录树烤成 ext4 镜像：

```bash
truncate -s 6G p1.img
mkfs.ext4 -F -q -L sdroot -d newroot p1.img     # -d 直接从目录建 fs
```

然后 MBR 用本地 Python 生成（512 字节，含 `0x8306c78f` 签名），dd 拼装三个分区镜像，全程用稀疏文件 + `conv=sparse` 避免撑爆空间：

```bash
truncate -s 12G sdcard.img
dd if=mbr.bin  of=sdcard.img bs=512 count=1 conv=notrunc
dd if=p1.img   of=sdcard.img bs=512 seek=8192     conv=notrunc,sparse
dd if=p2.img   of=sdcard.img bs=512 seek=12591104 conv=notrunc,sparse
dd if=p3.img   of=sdcard.img bs=512 seek=20979712 conv=notrunc,sparse
```

### 制作前的清理（减小体积、避免污染）

- 排除 `/proc /sys /dev /run /tmp /mnt/data /lost+found`、`/root/*.img`、`swapfile`
- 清空 `/var/log`、`apt` 缓存、`/etc/machine-id`（首次启动重新生成）
- `--one-file-system` 防止跨文件系统
- 补建 `proc/sys/dev/run/tmp/media/mnt/mnt/data` 空目录（tar 排除后需要）

### 验证手段（不占额外空间）

e2fsprogs 支持 `?offset=` URL 语法，可以直接对镜像内分区做检查，**不需要 loop 挂载**：

```bash
dumpe2fs -h 'sdcard.img?offset=4194304'
e2fsck -fn 'sdcard.img?offset=4194304'     # 结果: clean, 30440 files
debugfs -R 'cat /etc/fstab' 'sdcard.img?offset=4194304'
dd if=sdcard.img bs=1 skip=$((20979712*512+4086)) count=10 | od -c   # SWAPSPACE2
```

### 换卡即用的原理

PARTUUID = MBR 磁盘签名 + 分区号。镜像签名固定 `0x8306c78f`，所以任何卡烧出来 `sda1` 都是 `8306c78f-01`，和 boot 的 cmdline 对得上，**不用重新打包 boot**。

### 配套脚本

`/usr/local/bin/sd-expand.sh`（已部署到设备）—— 烧到大卡后把剩余空间建成 `sda4` 挂到 `/mnt/data2`。MBR 只剩一个分区槽位，所以不能简单扩展 sda2（被 sda3 挡住），建 sda4 是最安全可逆的做法。

详见 `SD卡系统镜像\烧录说明.md`。
